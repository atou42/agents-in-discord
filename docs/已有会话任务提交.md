# 已有会话任务提交

本文记录初版 Codex 既有会话入口。当前已泛化为接收实例自身 provider，并支持 settings 中的持续放行或逐项审批，见 [跨会话消息策略](跨会话消息策略.md) 和 [跨 Agent 入口启用](跨Agent入口启用.md)。

## 行为

在原 `submit-task.mjs`、Unix socket、请求记录和任务队列上增加 `--target-thread`，不另建 runner、thread、session 或工作区。任务使用目标 thread 的既有 Codex session、模型设置和工作区，不复制来源上下文。

目标必须是已开放、同 guild、未归档且未锁定的普通 thread，并已绑定 Codex session。不接管旁问、其他 provider、待 fork 或待压缩摘要的会话，不自动唤醒归档 thread。核对授权用户对来源与目标的访问权限；私有 thread 还核对成员身份。不要求目标的 CreatePublicThreads 权限，因为这里不创建 thread。

目标忙时进入原队列，不 steer 当前运行。发布可见的 bot 提交记录，包含完整 prompt、来源授权链接及请求 ID，长文本仍使用附件。它不是通过 messageCreate 触发，原有忽略 bot 消息的保护不变。

绑定时记录目标 session ID 和工作区；取到锁后再次检查。期间发生 reset、provider 切换或 workspace 切换，会失败而不是在另一个上下文运行。正常运行期间原有压缩、重试、取消、进度和结果展示机制不变。

## 授权与 CLI

授权仍须来自真实用户消息，但已有 thread 使用独立语法，不能拿“新建 thread”的授权替代。用户在来源 thread 发：

```text
!task-authorize jev-cross-20260919-01 thread 1550808791782785045
```

机器人确认后，Agent 用返回的授权消息 ID：

```bash
node scripts/submit-task.mjs \
  --socket /Users/atou/.aid-tasks/tasks.sock \
  --request-id jev-cross-20260919-01 \
  --target-thread 1550808791782785045 \
  --source-thread 1550810498470256691 \
  --authorization-message REAL_MESSAGE_ID \
  --prompt-file /absolute/path/任务提示.txt
```

`--target-thread` 与 `--parent`、`--title`、`--share-source` 互斥。验收 prompt 为“只回复 CROSS_THREAD_OK，不调用工具，不修改研究内容”。自然语言授权、同 UID 信任边界与原入口一致，不能伪造用户账号或授权消息。

## 状态与恢复

沿用原状态，新增 `thread_bound`，表示已绑定既有目标，并非创建了新 thread，也不表示 runner 已启动。已有 session ID 可以在启动前返回；只有 runner 启动事件才进入 `started`。

重复 ID 相同内容不再入队；不同目标或内容明确冲突。新建请求的规范化输入和指纹算法保持兼容，不改已有记录。

`thread_bound` 或 `queued` 重启恢复时，重新核对授权和目标绑定，通过原队列继续，不创建 thread，也不重复发送已记录的 prompt。`publishing` 或已可能运行的请求仍标记 `interrupted`，不自动重放。取消和移出队列使用原命令及已核实的用户归属。
